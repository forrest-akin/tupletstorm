Rhythm Tree Format

Every bar is a tree of equal splits, timed in exact fractions of a quarter note, and the whole groove fits in a readable link. Edit the link text or click the lanes below; each one rewrites the other.

    The model

    One node type, exact time

    A node splits the time it's given into n equal slots. Its children fill those slots; a child's weight says how many it takes. That's the whole structure. Mixed meters, per-beat subdivisions, lane polyrhythms and nested tuplets are all arrangements of it.

    Rules that keep it honest

    • No tuplet type. A split is a tuplet when its slots aren't plain note values. Three in a quarter is a triplet; three in a dotted quarter is plain 8ths. The rule below decides, so timing and notation can't disagree.
    • Ratios are labels. 6:4 and 6 play identically. The ratio only overrides how the bracket reads.
    • Time is a fraction, never a float. Onsets are rationals of a quarter note (a nested quintuplet starts at 22/15). Seconds are computed last, so long loops don't drift.
    • Slots, not ticks. Hits address leaves in time order, one letter each. Change a beat from 16ths to quintuplets and existing hits snap to the nearest new slot in the editor; the format never stores an onset that isn't on the tree.
    • Lanes are kit pieces. One articulation per lane per slot, using Groove Scribe's own letters. A crash and a hi-hat on the same slot are two lanes, so they can finally coexist.

    Tuplet rule

    When is a split a tuplet?

    Each slot is written as the smallest plain note value at least as long as its real length, dropping one size when that doesn't tile the span. The count of those written notes that fill the span is m. Inside a tuplet the same rule runs on written lengths: a triplet quarter is written as a quarter, so a 5 inside it is a 5:4 of 16ths. This table is computed by the module, not typed in.

    Link anatomy

    The current example, field by field

    The groove lives in the fragment, after #, so it never reaches a server and the editor can rewrite it on every change without reloading. Every character the format uses is legal unescaped in a fragment; only free text (title, author, comments) is percent-encoded.

    Grammar

    // nodes
node  := INT [ ':' INT ] [ '(' node { ',' node } ')' ] [ '@' INT ]
// bars, separated by ';'
bar   := INT '/' INT [ '~' INT { '-' INT } ] ':' node { ',' node } [ '*' INT ]
// lane hits, one bar per ';'
hits  := { letter | '-' | '-' INT } | '.'
// lane overrides, separated by ';'
ov    := lane '@' bar { '.' index } '!' node
// metric modulation: at bar, a unit note lasts as long as old did
tc    := bar ':' frac '~' frac

    Reading nodes

    Old links

    Every Groove Scribe link still opens

    A link without v=2 that carries Groove Scribe fields goes through the importer, which mirrors the original parser: case-insensitive field names, the same tolerant rescaling of tab lines that are too long or short, the same tempo and measure limits. Its letters map straight onto lanes.

    What the old format couldn't say

    • One TimeSig and one Div for the whole groove, so no meter changes and no beat-by-beat subdivision.
    • Triplet divisions only fit 2/4 and 4/4; the source logs a warning for anything else.
    • At most 10 measures.
    • One symbol per slot on the H line, so a crash can't land with the hi-hat, and kick plus hi-hat foot needs its own combined letter.
    • MIDI at 128 ticks per quarter, so 16th-note triplets fall on 10.666 ticks. The new module picks a resolution where every onset is a whole tick.

    In the fork

    Where it plugs in, and where the speed comes from

    The module is js/rhythmTree.js: pure, no DOM, written to the repo's conventions (ES module, JSDoc types, Vitest). It sits beside urlSerialization.js, the way the grooveData contract does today.

    1. Make the score the source of truth

      Today the grid's state is read back from each cell's rendered color (gridState.js) and assembled into grooveData on demand. Render the grid from the score instead, and have clicks edit the score. Undo becomes a stack of scores, or of link strings.

    2. Compile per bar, cache by text

      formatBar() plus that bar's overrides is a stable key. Keep each bar's leaves and events under it, and an edit recomputes one bar.

    3. Engrave per bar

      updateSheetMusic() regenerates the ABC for the whole groove and re-renders all of it through abc2svg on every change. Render and cache each bar's SVG under the same key and redraw only the edited one. Check that abc2svg handles the nesting depth you want; ABC's tuplet syntax doesn't express nesting cleanly, so deep tuplets may need a different engraver.

    4. Schedule with Web Audio

      A changed groove is currently rebuilt into a MIDI file and reloaded at the next loop (midiNoteHasChanged → loadMidiDataEvent). compileEvents() returns times in seconds; a lookahead scheduler reading them picks up an edit within one scheduling window instead of one loop.

    5. Export MIDI at an exact resolution

      midiResolution() returns the smallest ticks-per-quarter (at least 480) that puts every onset on a whole tick, and says whether it fits a MIDI header.

    6. Write the link lazily, read both formats

      Debounce history.replaceState with encode(score). decode() routes old query links through the importer, so shared links, bookmarks and the built-in groove library keep working, and the golden-master suite still covers the old renderer during the move.
