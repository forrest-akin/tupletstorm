# Handoff: plan the redo of `main`

Phase 0 (`3e31132`) was built before the user's methodology was loaded: one 14,175-line commit, a
bottom-up port of `docs/reference/rhythmTree.js`, and no caller for any of it (the web client never
loads the wasm package). The user chose to redo the code top-down and rewrite `main`'s history.
Write the plan to `.claude/plans/2026-10-26-redo-main.md`.

## Decided

- **Rewrite `main`.** A new root commit holds what's kept; the top-down commits follow. Build on a
  local orphan branch. `main` moves to its tip only after the tip passes in a clean worktree. The
  force push to `origin/main` waits for the user's explicit approval at that moment; no agent
  pushes.
- **Keep:** `docs/` (all of it), `tools/gen-conformance.mjs`, the conformance fixture, `LICENSE`,
  `.gitignore`, `mise.toml`, `.github/workflows/ci.yml`, `README.md` and `CLAUDE.md`. Each is
  rewritten wherever it describes code its commit doesn't have yet. The two existing handoffs land
  verbatim in commit 1, with the toolchain pins and CI jobs they seeded.
- **Redo:** `crates/`, `web/` source and the Cargo workspace files, top-down from the web
  client, starting with milestone 2's vertical slice (`docs/milestones.md`). Each core piece is
  built when the slice first calls it; conformance cases switch on as their features land.
  Old-link import, MIDI resolution and tuplet inference wait for the milestones that call them.
  Build config (`web/package.json`, lockfile, tsconfig, Vite config, `Cargo.toml`s) carries over
  only where nothing in it is ahead of its first use.
- **The old code is a source of findings, not code.** Whatever it decided that `rhythmTree.js` and
  the fixture don't pin goes into the plan, in the commit where it first applies.

### User decisions, 2026-10-26

- **No fuzzing** until v1 of all planned capabilities exists: no `fuzz/` crate, no nightly
  toolchain. The old target's shape stays in `findings-code.md` §4.
- **Test budget:** the strongest correctness checks whose suites still run to completion in under
  10 s each (target 5 s) after compilation, for `cargo test --workspace --all-features` and
  `npm test`. Property tests stay. Integration and e2e tests come later.
- **Only `main.tsx` is untested.** It loads the wasm package, reads `location.href`, builds the
  `history.replaceState` writer and mounts the app with those passed in. Everything it mounts is
  unit-tested: logic as pure functions, components in a DOM test environment (each new dev
  dependency justified in its commit body).
- **The grid draws from leaf slots.** Milestone 2's row reads "draws the bar grid from the bar's
  leaves"; tuplet inference and written values arrive with notation.
- **Lanes:** the editor shows every kit lane in `LANES` order, then the link's custom lanes
  (`docs/design/README.md`: "one lane per kit piece").
- **RFD files stay untouched.**
- **`main` moves at the end of this plan.** The local branch `phase0-original` (at `21ba10c`)
  preserves Phase 0. After the tip check, an agent compares it with the redo (size, tests and
  suite time, public API, dependencies, defects found, what the redo leaves out) and writes
  `.claude/work/redo-main/comparison.md` before `main` moves.
- **Play's scheduler, drum samples and swing** wait for RFD 0004.

## The plan contains

1. The root commit's exact file list, and how CI is green on it.
2. The commit sequence. Per commit: Conventional Commit subject; the failing test that drives it
   and why it fails; what it adds; the conformance cases it switches on; the docs it makes true;
   the checks that verify it. Each commit deploys alone.
3. The decoder's error model, settled before its code (`decode` never fails; problems are
   `Issue`s).
4. What needs a spike or a decision record first. RFD 0004 (audio scheduling) is in ideation, and
   milestone 2's Play depends on it. RFD prose is Forrest's: a decision the plan needs comes back
   as a user decision, never as RFD text.
5. The cutover: moving `main`, the clean-worktree check at the tip, and the force push left to the
   user.
6. User decisions, each with options, trade-offs and a recommendation first.

  edits, commits or pushes.
- Leave the untracked `.zed/` and `web/.prettierrc` alone.
